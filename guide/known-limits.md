# Known limits

Part of the [Subagent Router documentation](../README.md#documentation).

- **Agents that the Workflow tool starts are not routed.** The Workflow tool runs a script that starts many agents. Claude Code runs the routing hook only for calls of the `Agent` tool, and a workflow script starts its agents without that tool. So these agents keep the model that the script names, they take no writer lock, and a Codex worker started from a workflow stops with `CODEX_FAILED no codex-request line`. The log records only their start, their stop and their token counts. See [Calls the hook leaves alone](routing.md#calls-the-hook-leaves-alone).
- **Token counts depend on a format that Claude Code does not document.** The `usage` record reads the subagent's transcript, and waits up to 1.5 seconds for its end. A transcript written later than that, or an update of Claude Code, makes the counts `partial` or `unread`. The record then says so; it never shows a zero instead. Claude Code 2.1.281 to 2.1.289 also write no final output count for most replies that end in a tool call. Such a reply keeps only the count from its start. So on those versions `output` is a lower bound, often far too low (`stream_output`). Input and cache counts are complete. See [Log records](report-and-log.md#log-records).
- **The writer lock has gaps.** It does not cover edits by the main session, and calls to other agent types take no lock. After a real crash of a session, when no new process takes its writer over, the lock blocks other writers for up to one hour. See [The writer lock](writer-lock.md#the-writer-lock).
- **Codex workers stop inside Claude Code's Bash sandbox.** The sandbox denies writes to the data folder, so a worker cannot take over the task that the routing hook stored for it. It stops at once and says so, and the main session does the task with a Claude worker. Exclusion entries for a copy that no session can change lift this; a working checkout never qualifies. See [The Claude sandbox](codex.md#the-claude-sandbox).
- **The `codex:codex-rescue` redirect** blocks one known way to skip the routing, not all of them.
- **Codex reports zero tokens for a scoped review,** so the log has no token count for those reviews. A custom review and a consult report their tokens.
- **The Codex plan numbers can be old or missing.** The plugin learns them only after a Codex job that it started, from Codex's internal session files. A Codex update can change these files; see [Codex plan numbers](codex.md#codex-plan-numbers). When the plugin cannot read the numbers, the plan counts as unknown.
- **So a job can spend credits although `codexSpendCredits` is `false`.** When the saved numbers are old, the plugin can miss that a Codex window has reached 100 percent.
- **The routing table and the gates are first guesses.** A gate is the lowest confidence, or the usage level, at which a rule acts. The log shows where Jev and the main session disagree. It cannot show which route would have been better. That needs the same tasks with routing on and off; see [EVALUATION.md](../EVALUATION.md).
- **For another agent type, the hook does not read the agent file.** So the log cannot tell whether a rewrite changed the model that would have run. When the agent file already names the model of the table, the log still says `rewrite`. In `shadow` mode, the `launched` line shows the model that runs without a rewrite.
- **The finding triage only logs.** Its judgements reach no session until an evaluation passes, and that step is not built yet. Many review agents cite no `file:line`, and a finding without a citation gets no judgement, so a sample can take weeks to fill. For Codex jobs, only commit reviews give evidence; base, uncommitted and custom reviews are parsed and counted, but nothing of them is sent, because Codex compares them with the working tree, which can change before the triage reads it.
- **The Sonnet cap is narrow.** It covers only the routes that the table picks, and only while Codex cannot take work. While Codex can take work, a hard task that does not move to Codex still runs on Opus when Claude is near its limit. Examples: a call to another agent type, a diagnosis that changes no files, and a hard implement or debug task whose brief is not self-contained.
